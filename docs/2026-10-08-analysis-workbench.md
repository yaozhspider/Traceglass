# Traceglass 分析工作台改版

目标：参考代码 Agent 产品的高效交互，建立以样本、协作和可复核证据为中心的独立工作台。

## 交互设计

- 深色石墨底色、玉绿色分析/证据标识、琥珀色授权提示；沿用溯镜品牌。
- 导航优先显示分析会话，样本列表独立滚动；输入区保留上传和样本选择。
- 对话独立滚动，输入区固定。阅读历史时不追随新输出，提供最新进展入口。
- 工具调用按真实 call ID 合并输入/结果，失败、等待授权和未完成分别显示。
- 协作卡锚定第一个原生 AgentCreate/AgentInvite 调用。底部始终可进入实际团队。
- 子会话按需加载，展示委派说明、工具记录、授权入口和主待办的验收状态。
- 原生 idle 表示本轮空闲，不能视为任务完成；任务完成仍以主 Todo 状态为准。
- 文件面板按需展开。Markdown 报告支持表格和工作区内文件链接，不执行原始 HTML、不自动请求远端图片。
- 证据索引仅收录成功登记的记录及带真实证据 ID 的产物保存结果。提供来源、产物位置、哈希、置信标记和原始数据；登记不代表结论已验证。

## Agent 策略

完整/深入/详细逆向分析：主 Agent 先做简短身份核验，再写 TodoWrite，尽早使用 AgentScope 原生团队工具委派独立任务。通常 2–4 个成员，上限仍为 8，主 Agent 负责复核与最终报告。简单查询、不可拆分任务、用户指定单 Agent 时可直接处理。

保存旧默认提示词 V2 的精确内容，迁移仅匹配出厂默认；用户定制提示词、名称和迭代配置不被覆盖。运行中的旧 Agent 不会被伪造成已使用新规则。

## 代码边界

- `useWorkbench.ts`：页面数据、路由和提交协调。
- `WorkbenchShell.tsx`：工作区布局和面板选择。
- `SessionTimeline.tsx`：原生事件/消息呈现与授权交互。
- `timeline.ts`：工具配对、状态标签、委派定位和证据筛选，纯 UI 投影。
- `TeamPanel.tsx`：真实成员及懒加载子会话。
- `RecordInspector.tsx`：证据详情与原始记录。
- `Markdown.tsx` / `WorkspaceFileContext.ts`：安全渲染和工作区文件导航。
- `workspace.css` / `workbench.css`：工作区总览与分析工作台各自的样式。

不新增 Agent 调度器、计划执行器或模拟执行数据。

## 验证记录

- 自然任务“请逆向分析这个软件并给出详细报告”使用测试用 benign-true 样本；用户测试提示词未要求使用子 Agent。
- 主模型实际创建 struct-analyst、string-analyst、decompiler 三位成员；查看其原生会话、工具结果和主 Agent 对产物的复核。
- 浏览器验证：桌面与 390px 窄屏、固定输入区、成员展开、工具授权、上传后自动选择样本、目录浏览、文本/Markdown 预览与下载。
- 单元回归覆盖工具结果配对、缺失结果、失败/授权状态、委派锚点、证据筛选、工作区链接越界与报告相对链接。

样本分析内容来自模型，不因页面改版而获得额外真实性保证。未登记来源或置信标记时明确显示未标注。

## 沙箱文件编辑兼容修复

真实三成员验证发现 AgentScope 2.0.6 的 ToolContext 使用宿主机 getmtime，而 Read/Edit 使用工作区 backend，造成 Docker 内文件无法缓存。新增仅限本应用的 WorkspaceFileCacheMiddleware，保留原生缓存格式及权限处理，改用 backend.stat() 的完整 mtime。回归覆盖持久化、授权恢复、外部变更、文件删除和拒绝授权。

后端已在无运行任务时重启加载。真实 string-analyst 子会话在重新 Read 后，Edit 已返回成功（2026-10-08）。最终验证：86 项后端测试、41 项前端测试及生产构建通过；AgentScope 存在上游弃用警告。
