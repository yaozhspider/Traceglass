# 执行权限档位

输入区提供「请求批准」和「全部执行」。新分析默认请求批准，每个会话的选择写入 AgentScope 原生 `AgentState.permission_context.mode`，重新加载页面后恢复实际值。上传样本、模型与工作区配置不因切换而改变。

- 请求批准映射到 `PermissionMode.DEFAULT`：需要授权的工具操作进入原生确认流程，已有允许规则和只读工具仍可自动执行。
- 全部执行映射到 `PermissionMode.BYPASS`：普通工具调用自动执行，显式 deny/ask 规则及原生工具强制保护仍生效。不是 `DONT_ASK`（后者会拒绝需询问的操作）。
- 主 Agent 新建的子 Agent 使用原生模板权限继承。已有子 Agent 保留各自的权限，可在展开的成员面板中切换；主 Agent 的选择不会冒充整个既有团队的选择。
- 准备和运行阶段禁止修改；用户可以暂停或等待结束后切换。原因是 AgentScope 在运行开始时读取权限快照，中途修改会被忽略或被运行状态覆盖。
- 等待批准时可以切换；已发出的确认请求仍需明确批准一次，随后普通工具按新档位执行。切换档位本身不恢复或批准待处理调用。

新会话通过工作区创建接口携带 `permission_mode`。已有会话通过 `/product/sessions/{sid}/permission?agent_id=...` 修改：只允许两种产品档位，校验会话所有权和原生准备任务，再委托 AgentScope 原生更新处理器完成权限上下文持久化。该适配器依赖 AgentScope 2.0.6 内部路由接口，升级时需运行契约与原生执行测试。

验证覆盖新建默认值和显式值、非法档位、跨用户拒绝、准备/运行时冲突、双向切换、真实 Write 等待/自动执行、显式禁止/询问规则保留、等待期间切换后的原生继续，以及动态子 Agent 的权限继承。只替换测试中的外部模型传输，工具、确认、团队和数据库均使用真实 AgentScope。
