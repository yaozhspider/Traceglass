# 暂停、恢复与执行预算

## 用户行为

- 输入框旁固定显示“暂停全部”，主 Agent 或任一成员运行、准备环境、等待授权或外部结果时可用。
- 展开的成员会话支持单独暂停。中断、失败或预算用完的回复可点“继续执行”；也可在主会话发送新的分析要求。
- 暂停调用 AgentScope 原生中断，并取消该会话注册的后台工具任务。已保存的消息、工具结果、Todo 和工作区文件保留。取消协程不代表能够撤销已发生的文件操作，或保证外部 MCP 服务里的独立进程已经停止。
- 主 Agent 用 `TeamSay(to="成员名", content="新任务")` 可恢复同一个已中断/失败成员。保留会话历史，不新建替代成员，也不自动重放已中断的工具调用。模型根据当前状态决定下一步。
- 主 Agent 开始新回复时会收到自有成员的停止状态提示和恢复方法，避免把已中断成员误称为仍在工作。这是原生持久化记录的快照，不是额外的轮询调度器。
- 普通迟到消息、广播和成员回报不解除暂停。等待授权的工具也不会因重新委派而自动获批。

## 原生运行时与产品策略

默认 `TRACEGLASS_MAX_ITERS=2000`，主 Agent 和所有子 Agent 模板一致。启动迁移仅更新原先随产品发布的 24 步默认值及其团队成员，保留用户自定义配置。

最后一步保留给模型收尾：通过 AgentScope Middleware 注入当轮提示，并设置原生 `ToolChoice(mode="none")`。即使提供方忽略此设置，本地权限钩子也拒绝本次收尾的新工具操作。总结应包含已证实结论、证据位置、未证实推断、未完成 Todo、限制和下一步。成功结束这次回复不等于完成整个任务；系统不修改 Todo 完成状态。

成员收尾无法再调用工具，所以适配层将模型生成的正文通过原生 `TeamSay` 定向发送给主 Agent。它不生成新结论、不广播、不替主 Agent 验收。投递失败时保留原结论并显示提示。模型调用失败或不遵从文本输出约束时仍显示真实错误/预算耗尽，允许继续，不伪造总结。

“继续执行”使用原生 `/chat/` 的 `input: null`，让 AgentScope 在同一会话开启新回复，重置当轮计数并保留历史。没有实现无限外层重试，也没有另一套 Agent 调度器。

原生 inbox 自动唤醒在兼容层受暂停标记约束。点名委派仅允许同一团队的主 Agent 为自有 created 成员签发一次恢复标记，绑定停止时的最新消息；暂停会撤销该标记。标记随当前内存消息总线存在，不构成跨服务重启的持久任务队列。

## 上下文压缩

已使用 AgentScope `ContextConfig()`：每次推理前检查上下文，达到模型配置窗口的 80% 时触发原生压缩，默认保留比例为 10%。它与执行步数预算是两个独立机制。压缩后的运行上下文不等于完整原文；原生持久化会话仍可用于查看过程。

当前 OpenAI-compatible 适配器对未匹配模型卡的模型默认窗口为 128000 token；这不是对 GLM 实际服务窗口的验证。压缩机制已接入，不代表当前某次真实会话已经触发了压缩。
