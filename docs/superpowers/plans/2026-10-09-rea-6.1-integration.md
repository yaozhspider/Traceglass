# REA 6.1 integration implementation plan

**Goal:** Make the latest released REA usable from the existing workbench with its matching official instructions, discoverable workflows and durable shared evidence.

**Approved design:** The user approved the preceding five-step integration proposal and requested a baseline commit followed by an upgrade for testing. Keep AgentScope execution, permissions and per-agent REA sessions. Work sequentially in this conversation; no delegated agents. Baseline: `2b1f301`, tag `checkpoint-before-rea-6.1.0-20261009`.

**Architecture:** A versioned container overlay reuses the installed native engines without replacing the old image. A small adapter exposes MCP prompts through the same live connection. An AgentScope acting middleware copies evidence-bearing tool results into a product-owned SQLite store; read-only scoped tools and endpoints expose saved records to agents and the workbench. The store is an archive of observed outputs, not a second REA inference engine or a guarantee of analysis completeness.

## Constraints

- Pin npm `rea-agents@6.1.0`, verify its SHA-512 package integrity, retain upstream skill files and MIT license.
- Keep old kit, image, credentials, workspace data and user permission selections.
- No implicit tool execution when fetching prompts; absent prompt support must not disable analysis tools.
- Keep the original result and its limitations. Do not fabricate absent sample identities or promote inferred evidence to observed.
- Scope archive reads by user and workspace; namespace upstream IDs by REA connection instance and analysis session.
- Tool errors and failed archive writes must never appear as successfully archived evidence.
- Existing workspaces receive the new upstream skill; user-edited skills are not silently replaced.
- Persist archived evidence across service restarts. Reopen native targets after restart; do not claim engine state restoration.
