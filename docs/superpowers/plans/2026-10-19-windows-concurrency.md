# Windows 单机 8 并发实施计划

**目标：** 按已确认的单机共享方案，将本机 Windows 并发配置为 8；静态分析共享，普通程序可显式共享动调，恶意样本与未知目标默认独占。

**设计：** SQLite 持久化每个任务的共享/独占租约、批次与恢复屏障。任务使用独立目录、TEMP、调试器和操作 ID。终态共享任务在采集后释放自身槽位；打开的调试器、未确认启动和未完成操作继续保留槽位。恢复快照必须等待本批次全部任务收尾，不能覆盖其他任务或未采集的结果。

**文件：** `windows/scheduler.py` 负责事务与迁移，`windows/service.py` 负责执行与证据回收，`windows/config.py` 负责并发及自动恢复策略，`windows/tools.py` 和分析提示负责模型可见接口；来宾 worker 报告调试器失败清理结果。测试只替换 ESXi 外部边界，使用真实 SQLite 与多个服务实例验证竞争。

## 实施与验收

- [x] 先新增失败测试：8 个任务准入、第 9 个拒绝、默认动态独占、显式共享、重启持久化及旧租约迁移。
- [x] 实现每任务租约和只读容量查询，不向其他账号泄露任务 ID。
- [x] 新增失败测试并实现：独立会话操作、关闭并采集后释放、失败清理、最后任务恢复、跨实例恢复屏障、恢复失败保留阻塞。
- [x] 更新工具 schema、内置路由、说明和示例；私有配置设置 `max_concurrent_jobs=8`，默认保留显式恢复策略。
- [x] 运行 Windows 单元、目录集成与相关产品回归检查，自行审阅变更及备份差异。

**生效边界：** 此次只改代码和配置，不重启服务、不恢复当前 VM、不加载目标样本。管理员可配置 `auto_reset_on_idle`；未启用时最后一个共享任务仍保留待恢复状态，模型需沿用当前任务已有的恢复授权调用固定基线恢复。

**命令：** `.venv/bin/python -m pytest tests/unit/test_windows_concurrency.py tests/unit/test_windows_tools.py tests/integration/test_windows_catalog.py -o addopts='' -q --tb=short`

**验证记录：** Windows 与工具目录相关回归首轮 114 项通过；另补旧静态租约迁移场景，防止未配置动态基线的纯静态部署被错误标记为待恢复。生产状态库只做只读备份，在副本上验证旧失败独占任务迁移；当前运行服务未切换。

**最终验证：** 123 项相关回归通过（其中 Windows/目录 71 项）；版本冲突、启动期间恢复、过期批次启动、独立 TEMP 子进程继承，以及部分恢复失败后无需来宾访问即可回读旧报告均有回归覆盖。已保存报告会标明未采集的操作数，保留实际租约与恢复状态。未在真实 Windows 上加载样本或测试 8 个调试器同时运行。
