# 常见加解密与混淆方法参考

本文档用于生成候选和选择验证方法，不允许仅凭一个关键词直接下结论。每个候选都应回到函数、数据流、调用可达性和输入输出证据。

## 一、编码、压缩和校验

| 方法 | 常见识别线索 | 容易误判 | 建议验证 |
|---|---|---|---|
| Hex | 字符集仅为 `[0-9a-fA-F]`，长度通常为输入两倍 | 随机 token、哈希文本 | 解码后长度和原始字节是否一致 |
| Base64 | `A-Z a-z 0-9 + / =`，长度是 4 的倍数 | 自定义 64 字符表 | 多组输入编码结果和 padding |
| Base32/Base58 | 受限字母表，无明显标点 | 标识符、文件名 | 使用候选字母表逆解码 |
| URL 编码 | `%xx`、`+`、路径/查询参数 | 普通日志文本 | 解码后是否进入网络或配置解析 |
| zlib/gzip | `78 01/9c/da`、`1f 8b`，压缩库调用 | 随机二进制头 | 解压后 magic、长度和校验 |
| LZ4/Zstd | 库调用或格式 magic | 内嵌资源 | 解压并检查输出结构 |
| CRC32 | 查表、移位/XOR、固定多项式，输出 4 字节 | 自定义校验 | 已知输入和逐字节增量特征 |
| ROT13/ROT47 | 固定字符轮转，无 key；ROT47 覆盖可打印 ASCII | 简单字符串混淆 | 对字符集逐字节逆变换 |

## 二、哈希和 MAC

| 方法 | 典型线索 | 输出长度 | 关键验证 |
|---|---|---:|---|
| MD5 | 64 轮、四组状态、MD5 T 常量 | 16 字节 | 标准测试向量 |
| SHA-1 | 80 轮、5 个状态 word、消息扩展 | 20 字节 | 标准测试向量 |
| SHA-256 | 64 轮、Σ/σ、8 个状态 word | 32 字节 | 标准测试向量 |
| HMAC | 内外 pad（通常 `0x36/0x5c`）和底层 hash 两次调用 | 取决于 hash | key 改变时内外两层都变化 |
| PBKDF2/scrypt/Argon2 | 迭代计数、盐、派生长度、内存/时间参数 | 可配置 | 固定 salt/key 多组向量 |

哈希是单向变换。若模型声称“解密哈希”，应改为验证比对、字典、派生或协议用途。

## 三、对称加密

| 方法 | 结构指纹 | 常见参数 | 验证重点 |
|---|---|---|---|
| AES | S-box/Rcon、SubBytes/ShiftRows/MixColumns 结构或标准库调用 | 16 字节块，128/192/256 位 key | 模式、IV、padding、key 来源 |
| DES/3DES | 置换表、S-box、16 轮 Feistel | 8 字节块 | 奇偶位、轮密钥和模式 |
| 3DES EDE | DES-EDE 三次调用；2-key 时 K3=K1 | 8 字节块，CBC/ECB | 确认 E-D-E 顺序、K1/K2/K3 关系 |
| SM4 | 中国商用密码分组结构、32 轮、FK/CK 常量、S 盒 | 16 字节块、128 位 key | FK/CK、线性变换和端序 |
| RC4 | 256 字节 S 盒、KSA 交换、PRGA | 可变 key | 初始 S 盒和前 16 字节 keystream |
| ChaCha20 | quarter-round、旋转 16/12/8/7、`expand 32-byte k` | 32 字节 key、nonce、counter | counter/nonce 顺序和 little-endian |
| TEA | 两个 32 位 word、32 轮、`0x9e3779b9` | 128 位 key | delta 符号、移位、溢出 |
| XTEA | TEA 变体，轮密钥索引依赖 `sum` | 通常 32 轮 | key schedule 和解密方向 |
| XXTEA | 可变长度 word 数组、MX 轮函数、`delta` 累加 | `n > 1` 个 32 位 word | `z/y` 邻接 word、`q=6+52/n` 和 delta |
| Blowfish | P-array、S-box 初始化，Feistel | 8 字节块 | key 扩展是否内嵌 |
| CTR/CFB/OFB | 计数器或反馈状态，非传统块填充 | nonce/IV | 每块状态更新顺序 |
| XOR/滚动 XOR | XOR 循环、key 重复或随位置变化 | 任意 | key 周期、初始偏移、是否叠加 ROL/ADD |

不要仅因为出现 XOR 就认定为 XOR 加密；必须确认它是输入到输出的主要可逆变换。

## 标准算法的魔改变体

索引中的 `*_c`、`*_cpp`、`*_go` 是实现语言，不是不同算法。`standard` 和编号变体应先归一到标准算法，再单独记录魔改层：

| 魔改层 | 典型例子 | 分析要求 |
|---|---|---|
| 常量替换 | TEA/XTEA `delta` 改为 `0x61C88647` | 不要只匹配标准 delta；记录实际常量和符号方向 |
| 轮数变化 | ChaCha12、TEA 8 轮、`16 cycle` | 从循环边界或计数器确认实际轮数 |
| S 盒变换 | S 盒每项 XOR `0x5`、AES `S[i]^0x63`、自定义 S 盒 | 比较完整 256 项映射及其逆映射 |
| 线性层变化 | AES ShiftRows 改为 `0,2,3,1`；ChaCha sigma 修改 | 记录置换/常量矩阵，不要按算法名套标准实现 |
| Feistel 结构变化 | DES 去掉 IP/FP；SM4 FK 各字 XOR `0xA5A5A5A5` | 分开记录初始/最终置换和密钥扩展常量 |
| MX 轮函数变化 | XXTEA 的 `z>>4^y<<3`、`y>>2^z<<5` 等移位修改 | 逐项记录 MX 表达式、移位方向和溢出 |
| 状态白化 | 整段或每轮 XOR `0xA5`/`0xA5A5A5A5` | 分离白化发生在输入、轮间还是输出 |
| 密钥流后处理 | RC4 输出 XOR `0xAA`、ChaCha 密钥流 XOR `0xA5` | 先验证原始 keystream，再验证后处理 |
| 密钥流初始化/丢弃 | RC4 初始 `S[i]=i^0x5A`、`drop256` | 确认初始 S 盒、KSA 后丢弃长度和输出后处理 |
| 轮间状态变换 | TEA/XTEA 每轮加法后 XOR `0xA5A5A5A5`，或 v0/v1 分别白化 | 标注发生在加法前、加法后还是轮末 |
| DES 密钥关系 | 2-key 3DES（K3=K1） | 不要把 2-key EDE 误标成普通 3DES 三密钥 |
| 组合变换 | S 盒 XOR + 分组首尾白化 | 按阶段拆分，分别验证每层可逆性 |

魔改样本的结论格式应类似：`AES-like/custom S-box + CBC + post-round XOR`，而不是直接写“标准 AES”。

## 四、非对称和密钥交换

| 方法 | 典型线索 | 验证重点 |
|---|---|---|
| RSA | 大整数乘法、模幂、模数/指数、ASN.1 | modulus、padding、签名还是加密 |
| ECC/ECDSA | 椭圆曲线点加/倍点、有限域乘法 | 曲线参数、签名格式、随机 nonce |
| Diffie-Hellman | 模幂或椭圆曲线共享点 | 公钥/私钥角色和共享密钥派生 |
| Ed25519 | 固定曲线常量、点运算、64 字节签名 | 公钥、签名和消息拼接 |

## 五、字符串和数据解密

| 方法 | 识别线索 | 验证方式 |
|---|---|---|
| 栈字符串构造 | 逐字节写栈、立即数拆分、函数返回前拼接 | 断点或仿真后 dump 缓冲区 |
| XOR 字符串 | 常量 blob + 短循环 + `xor` | 修改 key/输入后比较明文 |
| API 哈希 | 字符串缺失、导出表遍历、哈希比较 | 重建哈希并匹配系统导出名 |
| 运行时解包 | 分配可执行内存、解压/解密后间接跳转 | 解密点内存快照和控制流 |
| Go/Garble 字符串 | runtime 相关函数、批量短字符串恢复 | GoReSym/运行时调用点/多字符串复核 |

## 六、代码混淆

| 类型 | 典型特征 | 首选方法 |
|---|---|---|
| 控制流平坦化 | dispatcher + 状态变量 + 间接跳转 | 恢复状态转移，清理 CFG |
| 不透明谓词 | 复杂但恒真/恒假的条件 | SMT 求解和路径采样 |
| MBA | 加减乘 XOR/NOT 的复杂等价表达式 | LLVM/P-code 归一化和代数化简 |
| 虚假控制流 | 不可达块、无效异常路径、死代码 | 可达性分析和 CFG 清理 |
| 间接调用 | 函数表、跳板、动态解析 | 解析表和调用目标追踪 |
| API 哈希 | 遍历模块导出并比较自定义 hash | 识别 hash 循环并批量反查 |
| 自定义 VM | opcode 分发、寄存器数组、解释循环 | 提取 opcode 语义并建立 VM IR |
| 反调试/反虚拟机 | ptrace、时间差、CPUID、设备/进程检查 | 先标注保护边界，再做受控绕过实验 |
| 控制流/字符串双重混淆 | CFG 和数据同时不可读 | 先恢复字符串和关键 dispatcher，再分析业务路径 |

## 七、统一验证模板

面对任何候选方法，按以下顺序收集证据：

1. **候选**：记录类别、算法名、来源工具和初始置信度。
2. **结构**：记录位宽、端序、块大小、轮数、常量、查表和状态变量。
3. **数据流**：确认输入、key/IV/nonce、状态和输出是否同属真实调用链。
4. **复现**：先生成语义 IR，再在 Sandbox 中写 Python 或其他复现程序。
5. **差分**：至少使用多组输入；必要时比较第一轮、中间轮和最终输出。
6. **结论**：仅在证据一致时升级为 `supported` 或 `validated`；失败实验保留为 `rejected`，不得覆盖。

## 八、常见反证

- 算法名只出现在未调用的字符串或导入表中。
- 代码块大小、输出长度或轮数与候选算法不匹配。
- key/IV 来源无法连接到目标函数。
- 只有一组输入吻合，换一个字节即失败。
- Python 输出“可读”但没有和样本输出逐字节比较。
- 混淆行为被误当成数据加密，或字符串编码被误当成密码算法。
