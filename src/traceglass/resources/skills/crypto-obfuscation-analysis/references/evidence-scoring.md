# 证据评分和结论状态

建议使用可解释的加分制，而不是让模型凭总体印象判断。分数是排序工具，不是数学证明。

| 证据 | 建议分值 |
|---|---:|
| 仅字符串/关键词命中 | 0.5 |
| 导入 API 或标准库路径命中 | 2 |
| 算法特有常量、S-box 或轮结构 | 3 |
| 块大小、轮数、端序与算法一致 | 2 |
| 调用链可达且 key/输入/输出数据流一致 | 3 |
| 一组输入输出吻合 | 3 |
| 多组输入和中间状态均吻合 | 6 |

状态规则（算法归因、复现实现、当前样本恢复必须分开填写）：

- `candidate`：存在初步线索，尚有关键缺口。
- `supported`：静态结构、数据流和调用关系相互支持，但未完成充分动态验证。
- `validated`：目标对象的多组输入和必要中间状态吻合。标准测试向量最多只能验证“复现实现”，不能单独证明样本使用该算法；可读字符串、魔数或自造 round-trip 也不能单独验证当前样本恢复。
- `rejected`：反证或实验失败，保留失败工件，不覆盖旧实验。

必须单独记录反证，例如：函数不可达、命中只来自未调用的库、输出长度不符、端序或轮数矛盾。

执行状态另行记录：`not_run`、`completed`、`failed`、`timeout`、`blocked`。
依赖缺失、路径错误、架构不兼容和超时只说明实验没有完成，不得直接把算法状态改为 `rejected`。
