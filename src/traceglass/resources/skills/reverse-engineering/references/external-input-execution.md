# 外部输入到代码执行的证据核查

用于网络/IPC 接收、消息解析、插件加载、脚本运行等路径。目标是确认输入是否能控制
高影响操作，同时区分固定初始化、受限操作和实际的远程执行能力。本资源是方法，不是
任何样本的证据；默认静态只读，动态验证继续遵守现有 Runtime Sandbox 边界。

## 先产出路径检查表

每条相关路径填一行，直接放入现有报告的机制、风险或覆盖章节，不增设报告类型。

| 输入/入口 | 变换 | 条件/分派 | 最终操作与参数来源 | 支持/反证位置 | 状态、缺口及下一步 |
|---|---|---|---|---|---|
| 接收函数/回调及实际调用者 | 解密、解码、解压、切片等 | 认证、前缀、操作码、白名单 | 执行/加载/启动/仅显示；哪些参数可控 | 文件哈希、地址体系、调用和原始片段 | 静态支持/在该路径排除/未解；动态另记 |

不把“可能执行代码、已成功执行、有恶意目的、有管理员权限”合为一条结论。每个主张分别给证据。

对有执行接口的路径，明确填写三个状态：**调用归属**（入口/接收/初始化/未知）、
**执行参数控制**（外部输入/固定内容/未知）、**动态观察**（未运行/观察成功/失败/受限）。
接收函数能调用执行接口，但执行参数仍未知时，只写“接收路径含执行调用，参数控制待查”；
不能升级为“输入可控执行”“远程代码执行已支持”，即使后文另列参数缺口也不行。

## 双向追踪

1. **从输入出发**：定位真正处理数据的循环、线程、回调和错误分支，追踪缓冲区及返回值；
   穿过解码、解密、拼接、切片和对象转换，直到显示、存储、业务操作或执行。
2. **从执行点回溯**：检查 `exec/eval/compile`、Python C API、脚本引擎、命令启动、
   动态加载和反序列化等候选。API 命中本身不是后门；核对每个相关调用的参数、调用者、
   可达分支和外部输入控制范围。动态名称、通用方法调用、函数指针也可能承载上述能力。
3. **闭合分派与参数**：核实比较对象、成功/失败跳转、前缀长度、切片边界、参数顺序、
   返回值以及异常路径；区分“可到达的执行分支”和“运行时已成功执行”。只查导入/字符串不算闭合。
4. **核对触发约束**：认证对象是谁、谁能提供内容、是否固定命令/白名单、输入是否足以
   改变代码。加密与认证约束来源，不自动约束来源能要求客户端做什么。
5. **界定权限**：执行受客户端进程/线程的有效安全上下文、令牌、沙箱和实际限制约束。
   普通用户进程的远程执行不能写成自动提权；权限未经验证时标未知。

示例：若工具证据闭合 `recv → decode → startswith("exec:") → text[5:] → Python执行接口`，
可以报告“静态支持服务端输入在匹配分支进入代码执行”。随后核实连接建立、认证和执行上下文。
`exec:` 仅为示例；其他前缀、操作码、别名、加密内容和间接分派采用同一方法。不要生成攻击载荷。

## PyInstaller / Cython / 原生扩展

- 解包成功、模块名像演示程序、AES 实现正确，只证明包装或算法的部分属性；继续检查应用模块的接收与分派。
- 用 `PyMethodDef`、类型方法表、回调注册、包装器到实现的调用和异常展开信息定位函数。
  `/GS` 序言只是编译器模式；`PyInit_*` 名字附近、相似序言或运行时错误文本不是函数归属证明。
- 对 `PyObject_Vectorcall*`、属性访问和间接调用，恢复方法名对象与实际参数；不能统一归为运行时噪声。
- 字符串压缩/全局对象表未解时，追踪表初始化与交叉引用；必要时用沙箱内只读解析脚本恢复。
  验证压缩输入消耗量、输出长度、记录边界、编码和引用关系。整个池可能混有文本与字节数据。
- `PyRun_StringFlags` 等按官方函数签名和调用约定解释各参数。`start` 指定语法输入模式，
  不是“模块初始化”标识。判断执行用途必须核查源码/代码对象的来源及实际调用链。
- 只有在相关调用路径及参数确认为固定初始化数据时，才把该调用限定为初始化；这个结论
  不自动覆盖其他调用点、未解接收函数或回调。无需导入或加载样本来读这些结构。

## 覆盖与停止条件

先给输入入口、分派点和高影响操作建立短清单。预算不足时，选最可能改变核心判断的一条
未闭合路径；必要时暂停算法复现，交付带明确缺口的阶段报告，而非用工作量换取高置信结论。
纯算法任务仍可报告算法结果，但不要顺带外推整个程序安全。

负面结论必须说明已检查入口/调用点、未解分支和工具边界：

- 全文字符串无命中、导入缺失、未发现域名/持久化，都不能单独排除执行能力。
- 记录反汇编扫描的区间、解码字节量、失败/跳过位置、截断和函数恢复限制。字节解码完整
  也不等于语义/控制流覆盖完整；部分扫描无命中只能描述该范围。
- 工具不可用、反编译为空、池未恢复时，换已配置静态工具或写有界解析器；仍未解则保留未决。
  空反编译的原因也须核查：可能是边界识别、格式/架构支持、工具错误或超时，不能直接确认为边界问题。
- 已有报告、模型笔记、重新编号的证据条目和同一中间输出的多份摘要不算独立佐证。
  追到原始工件、哈希、地址和指令；先检查能推翻当前判断的反例。

## 防止误报的竞争解释

| 证据情形 | 可以说什么 | 还不能说什么 |
|---|---|---|
| 只有执行 API 或 `exec:` 文本 | 候选执行能力，需查引用与参数 | 已有远程代码执行/后门 |
| 固定启动源码进入执行 API，已查网络分支仅显示 | 所检查调用用于初始化/显示 | 所有未解分支均安全 |
| 远端输入受固定命令映射约束 | 报告实际允许的操作和绕过检查缺口 | 任意代码执行 |
| 认证远端输入进入通用代码执行 | 受认证约束的远程执行能力与权限边界 | 认证使其没有风险；自动提权 |
| 代码路径成立但没有执行观察 | 静态支持该能力及触发条件 | 已观察到利用/入侵成功 |

确认远程执行能力后，是否称为后门还需结合预期功能、授权边界和隐藏触发机制。
能力可以明确报告，动机和部署情况不足时保持未决；不能因动机未知而删除能力发现。
