# 逆向分析报告规范

本规范仅适用于静态逆向任务的 binary 模板。恶意软件、行为核查和加解密任务按 [任务报告规范](report-profiles.md) 选择对应模板，不能强制套用本文件章节。binary 报告按下列八章及附录 A 排列，二级标题名称和顺序固定；分析重点通过三级标题按样本调整。报告题目使用一个一级标题：`# 样本名称 逆向分析报告`，其后注明分析日期、case ID 和版本。

开始分析时将各章的关键问题纳入工作项；结束时依据实际证据填入结论。没有证据的分析点写明“未评估：原因、对结论的影响、后续验证方式”；确定不适用时写明理由。无需为了填满章节启动额外实验。进度答复和局部函数问答可以简短；正式报告须符合本规范。

## 1. 执行摘要

- 用一段话说明样本角色、主要功能、分析方式及整体结论。
- 列出最重要的 3–5 项发现；发现较少时按实际数量列出，每项带关键证据引用与置信度。
- 说明最影响判断的覆盖缺口。产品身份、签名数据存在、签名有效性、恶意性分别判断。
- 摘要引用后文结果；不在摘要首次引入正文未支持的结论。
- 摘要中的触发条件、操作对象、尝试/成功状态与正文逐项一致。例如“打开句柄失败后，枚举未找到目标才尝试启动”在摘要中仍保留失败与未找到两个条件。

## 2. 样本身份与分析范围

- 身份表：文件名、SHA-256、大小、格式、架构、位数、端序、版本/编译线索；缺失字段说明未获取。MD5 可作为辅助标识。
- 分析目标与范围：本次要回答的问题、包含的文件/模块、未提供的关联组件；区分主文件和附带样本。
- 方法边界：实际使用的静态/动态方式和关键工具版本；未执行的检查标明未执行。时间戳和资源字符串是可修改的身份线索。
- 复用历史证据时注明来源轮次和样本哈希匹配方式。

## 3. 文件结构与保护特征

- 根据 PE/ELF/Mach-O/托管程序等格式检查入口、地址基准、节区/段及权限、导入导出、符号、资源、附加数据。
- 分开说明原始大小、虚拟大小、VA/RVA/文件偏移，解释关键区域用途。
- 检查壳、混淆、反调试、运行时解码或动态解析的实际证据及影响；熵、签名、壳检测未测时不写测量结论。
- 字符串/API/启发式命中用于定位候选，应回到代码确认；PDB 路径残留不等于持有完整调试符号。

## 4. 程序架构与执行流程

- 给出入口、初始化、运行模式/命令行分发、主循环和退出清理的全局流程。
- 用模块/函数职责表说明关键函数地址、调用关系、线程/进程、外部组件依赖。
- 对复杂样本给出有证据支持的 Mermaid 调用图、流程图或状态图；推断的边标为推断。简单流程可用简短调用链。
- 说明重点函数的选择依据和覆盖范围；排名特征不完整时披露退化，不把低分解释为低风险。

## 5. 核心功能与实现机制

这是报告主体，按实际功能组织三级小节，不按工具调用先后组织。每个关键功能采用以下分析单元，可以用紧凑表格表达：

| 分析项 | 必须说明 |
|---|---|
| 功能目的 | 该功能在程序中的作用；推断的用途标明推断 |
| 触发条件 | 参数、事件、状态、权限、前置检查及分支条件 |
| 关键位置与调用链 | 函数起点、调用者/被调用者，必要时给出关键指令地址 |
| 参数与数据流 | 输入来源、关键常量、路径/缓冲区构造、返回值去向 |
| 分支与生命周期 | 成功/失败、重试/超时、循环条件、状态转换及资源清理 |
| 系统副作用 | 文件、注册表、服务、进程、内存、网络等操作；区分尝试与成功 |
| 证据与边界 | 真实工具调用或工件引用、置信度、未恢复参数/未解分支及影响 |

缺失的具体参数填写“未提供/未恢复”。同一函数中的读取路径和写入路径分别追踪，不用已知写入路径补出未知读取路径；未提供函数之间的调用边则明确标为未恢复。

保留解释机制所需的短代码片段；完整反编译放附录工件。动态验证结果放在对应功能内，明确输入、观察、重复条件和与静态推断是否一致。未开展动态验证不需要伪造独立“动态分析”章。

对 Windows 服务类样本，常见小节包括命令行分发、主服务生命周期、控制处理与状态转换、守护/恢复、子服务编排、启动项和防火墙配置。按该样本实际发现选择，其他平台不用套用这些功能。

## 6. 关键数据、配置与算法

- 恢复关键结构体、全局状态、配置表及其读写者；重要字段列出类型/偏移/含义/引用位置。
- 配置按“键/位置 → 默认值与来源 → 解析/变换 → 使用者 → 行为影响”说明，覆盖路径、服务名、端口、注册表项等实际线索。
- 发现协议时分析消息格式、字段长度/字节序、状态机、校验及端点来源；配置端口不代表实际监听或 C2。
- 发现算法时给出候选依据、输入输出、参数来源、关键循环/常量、调用场景和验证状态。常量、枚举、GUID 的数值及地址映射必须可复核。
- 只做字符串扫描不能声称已排除加密或协议能力；未恢复的结构和算法明确留作未决项。
- 枚举只有数值证据时保留原值；只有核对可引用的接口/SDK 定义后才填写符号名。没有核对条件时写“名称未核对”，不凭记忆、邻近日志或其他字段的值猜测枚举含义。

## 7. 安全行为与风险评估

- 将已确认的权限需求、持久化、进程/内存操作、网络行为、数据访问和信任边界与证据关联。
- 区分合法功能、可被滥用的能力和明确恶意逻辑；产品名称、数字签名及工具标签不能替代行为判断。
- 若报告漏洞，给出触发条件、可控输入、前置权限、影响及验证状态；未做 ACL/搜索路径检查不能断言无风险。
- 有检测用途时给出检索线索/IOC 及来源、上下文和误报限制；无需求或无证据时不强行生成检测规则。
- 负面结论限定于实际检查范围，说明关联组件和动态路径是否覆盖。

## 8. 分析覆盖、未决问题与后续验证

- 使用覆盖表：分析对象/问题、已完成检查、状态、证据、缺口及影响。状态可为“已分析、部分分析、未评估、不适用”。
- 集中列出未解间接调用、缺失参数/工件、后端失败、截断和矛盾证据；未核实影响时写“影响待定”。
- 按对结论的影响排序后续验证，说明要验证的假设、所需输入/工具和可判定的结果。
- 区分执行结束、结构合规和分析覆盖充分。模型轮数、token 消耗和工具优化建议属于流程复盘，不放进样本正文。

## 附录 A. 证据索引与复现方法

- 证据表：E-ID 或真实调用 ID、支撑的发现/章节、工具来源、样本地址、实际工件路径、已有内容哈希、采集方式/版本。未知哈希写未提供。
- 关键命令和复现前提、完整反编译/CFG/解析脚本的真实位置；复用证据注明轮次。VA 到文件偏移的转换说明映射依据。
- 仅引用已存在的工件与真实调用；目录名称或 evidence ID 的存在不证明实验执行过。题面标签和历史笔记不得冒充当前归档文件。
- 方法代码未经执行时标为“建议复现步骤，未执行”；不得附编造的输出、实验目录、时间或哈希。

交付检查：完整草稿调用 `validate_reverse_report(report=...)`，工具自动保存正文、版本哈希和结构问题；据此修正。最终回复交付完整正文，不能只给总结或“见上一条”。即使格式仍有问题，CLI 与网页端也保存并交付可读草稿，注明未完成项；结构问题不允许导致没有报告。`save_analysis_artifact(artifact_path="report.md", ...)` 可保存最新版本，旧版本保留。校验不证明事实正确；证据引用存在性检查也不证明其内容支持结论。

代码与结果交付：模型编写的解析、解码、验证脚本必须保存源码文件；实际执行后保留输入、命令、stdout/stderr、退出状态及结果文件，引用当前 case 的实验路径。未执行代码标为“保存但未执行”，不要附想象的输出。静态反编译文本可作为代码证据保存，不能冒充可运行的复现程序。

复核规则：对命令行分发给出字符串比较位置、相等分支目标和副作用；不能按选项字母猜语义。入口创建的线程/注册的回调属于核心覆盖范围，空反编译结果应切换可用静态后端。附录实验必须引用实际文件清单；空目录的 metadata_only 只证明保存了登记信息。自动归档的 source.py/output.txt 是实际工具调用证据，整理脚本的内容哈希不同则不能声称同一版本已执行。报告正文不要写自身文件的 SHA-256（写入后内容会变化），由运行器的 report-validation.json 提供最终哈希。
