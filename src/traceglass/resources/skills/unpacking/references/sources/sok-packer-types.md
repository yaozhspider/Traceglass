# 运行时壳的复杂度分类（本地摘录）

出处：Ugarte-Pedrero, Balzarotti, Santos, Bringas, *SoK: Deep Packer Inspection*, IEEE S&P 2015。下面是分析时要用的定义，不必再打开论文。

## 旧工具常错的四条假设

1. 存在某一时刻，原始代码已经全部在内存里。
2. 多层壳按顺序解开，原始程序一定在最深一层。
3. 壳和原程序分开执行，有一个明确的 tail jump 到 OEP。
4. 解包和原程序在同一进程，没有跨进程通信。

Type IV 以后这些假设开始失效。单次 OEP dump 只对前几类可靠。

## 用来分类的概念

**层（layer）**  
程序刚加载时的指令属于 L0。若某地址被另一层写过、随后又被执行，它属于更高一层。一层是 `(已执行指令集合, 这些指令改过的内存)`。  
若一块内存先被 L4 写、再被 L2 改，它仍算更深的层（取写过它的最高层再加一），因为可能是浅层回来做最后一次修正。

**转移**  
从 Li 执行到 Lj（i≠j）就是一次层转移。只向前、每层一次，叫线性；出现回到更浅层的跳转，叫循环。两个线程分别跑不同层、靠调度来回切换，也算循环。

**隔离 vs 交错**  
简单壳先跑完解包，再 tail jump 到原程序。交错壳会在原程序执行期间继续跑壳代码，例如把 IAT 指到壳里的跳板，或在原程序里插保护检查。

**帧（frame）**  
一次「先写、后执行」的内存区域。传统壳每层一帧（single-frame）。一层被拆成多块、用一块解一块，就是 multi-frame。

**代码可见性**

| 方式 | 内存里能看到什么 |
|------|------------------|
| Full-code | 跳到 OEP 之前，原始代码已经全部写好。此时 dump 最完整 |
| Incremental | 只在即将执行前解开下一帧。OEP 处 dump 只有第一帧。跑完再 dump，能拿到已走过的路径；没执行的路径仍是密文 |
| Shifting-decode | 一帧执行完再重新加密。必须多次 dump 再拼接，单次快照永远缺块 |
| 异常重定向 | 页标成不可执行，触发异常后由壳解开该页再继续。Armadillo、Beria 用过 |
| Hook 重定向 | 在原代码里插入 INT 3 等指令，异常时把控制权交回壳。ZipWorxSecureEXE 用过 |
| 内联 | 编译期或二进制插桩，在函数前后直接放解密/再加密例程。Backpack、Themida 的宏保护属于这类 |

**粒度**（只在不是一次解完全部代码时有意义）：页、函数、基本块或单条指令。越细越难一次 dump，运行也越慢。

**并行**  
Dropper 写文件再执行，或开新进程注入。只有进程之间互相写对方地址空间，才把这些进程算进壳。线程数同样要记。

## Type I–VI

复杂度按「拿到原始程序有多难」算，不是按壳自己的代码有多花。

| Type | 结构 | 代表与后果 |
|------|------|------------|
| I | 一个解包例程，然后 tail jump。原始程序在第二层 | UPX。OEP 处一次 dump |
| II | 多层，每层顺序解开下一层，最后一次转移把控制权交给原程序 | 要等到最后一层；中间层不是载荷 |
| III | 多层，但拓扑里有环。原程序不一定在最深层 | 最深层经常是完整性检查或反调试。仍有 tail transition 把壳和程序分开 |
| IV | 单层或多层。壳里不负责解包的那部分，会和原程序交错执行 | 仍有一个时刻原始代码已全部解开，但 tail jump 难认，因为之后还会在层之间来回跳 |
| V | 交错，且承载原程序的那一层有多帧，一次只解一帧 | 有 tail jump，但当时只有一帧。执行结束后的快照能拼出已执行代码 |
| VI | 任一时刻只露出极小片段，可小到一条指令，用完再收走 | 必须多次 dump 再拼接。用字母标粒度，例如 VI-F 表示函数级 shifting-decode |

所有类型都可以再加「N 个线程 / M 个进程」。例如「4 线程的 Type I」。

中间层自己按函数解密、但原程序是一次解完的，分类上仍是 Type III。多帧只在它挡住「原程序」时才升到 V/VI。

## 分析框架实际记了什么

实现基于 BitBlaze 的 TEMU（QEMU）。跟踪基本块，并处理中断和异常。跨进程看远程写、共享内存、磁盘 I/O、内存映射文件。页 unmap 或 free 视为把已解开的代码收走。

每个字节用影子内存记状态：

- O：未知
- X：没写过就执行了（只可能出现在 L0）
- W：写过还没执行
- U：写过之后又执行了

另外记录：这块内存是模块、堆还是栈；每层调用了哪些 API；间接 call/jmp 的目标，用来事后猜 IAT。`GetCommandLine`、`GetVersion`、`GetModuleHandle` 一类初始化 API 常被当作「已经到原程序」的启发式，但只是线索。

## 对脱壳决策的直接用法

- Type I–III 且 full-code：在 tail jump / 候选 OEP 停一次，dump。
- Type IV：可以等到「全部已解开」，但不要把第一次跨层跳转当成结束。
- Type V：OEP dump 不完整；尽量跑完再取已执行路径，并注明未覆盖路径仍加密。
- Type VI：规划多次快照和拼接，不要承诺一份完整映像。
