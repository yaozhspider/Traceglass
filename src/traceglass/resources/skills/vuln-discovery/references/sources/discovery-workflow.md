# 挖掘流程（本地摘录）

## 五个阶段

只做到第 4 阶段的「确认」。第 5 阶段的利用开发、绕过 ASLR/DEP、武器化不在本 skill 里。

1. **侦察。** 版本、依赖、配置、文档和已有 CVE。CVE 用来知道历史上哪类 bug 出现过，用来指导去看哪段代码，不用来复述利用。
2. **静态。** 有源码就读解析和校验；没有源码就反编译入口到 sink 的路径；有补丁就先 diff。
3. **动态。** 在授权环境里用受控输入看系统调用、文件和分支。污点分析回答「这个字节有没有流到危险操作」。
4. **Fuzz。** 合法种子、只包住目标函数的 harness、覆盖率、sanitizer、崩溃去重。
5. **到此停止。** 把确认的缺陷写成报告。若用户另行要求修复，给出校验、类型和权限上的改法，不给出攻击步骤。

## 方法各自擅长什么

| 方法 | 找得到 | 找不到或很弱 |
|------|--------|----------------|
| 人工读信任边界 | 鉴权缺失、业务状态、错放的校验 | 大解析器里的罕见长度组合 |
| Semgrep | 局部语法模式，改一条规则就能扫很多仓库 | 跨函数、跨过程的深层数据流 |
| CodeQL / Joern | 源到 sink 的数据流、变体 | 没构建出数据库的仓库；二进制要先有中间表示 |
| 覆盖引导 fuzz | 解析器、编解码、内存破坏 | 要登录态、长状态机、严格校验和的路径 |
| Sanitizer | 把内存错误变成确定报告 | 逻辑漏洞、纯鉴权问题 |
| 符号执行 | 解开挡在 fuzzer 前面的少量复杂分支 | 整个程序；路径爆炸 |
| 补丁 diff | 漏补的兄弟函数、不完整修复 | 补丁把算法换掉、无法对齐时 |
| 依赖/SCA | 版本落在已知漏洞范围 | 项目根本没调用到漏洞函数 |

组合方式：fuzz 负责大范围撞路径；符号执行只在 fuzzer 卡住的分支上解约束（Driller、SAVIOR 这一路）。静态告警用来给 fuzzer 指方向，再用 sanitizer 把告警变成真阳性。SAST 单独报告的是假设，因为抽象会误报。

## 攻击面怎么列

每个入口写四列：谁能调用、输入形状、进入后第一个解析函数、最终能碰到的敏感操作。

敏感操作包括：命令执行、SQL/查询拼接、路径拼接、反序列化、模板渲染、内存拷贝、分配大小来自外部、跨用户读写、内核拷贝、发起到内网的请求。

优先序：

1. 历史上这类组件出过 CVE 的解析器。
2. 新代码和最近改过的边界检查。
3. 权限检查和业务操作不在同一个函数里的路径。
4. 第三方库的直接调用点，而不是库的全部源码。

## 确认等级

- **observation：** 工具输出或读到的代码事实，还没连到入口。
- **hypothesis：** 入口和 sink 在图上连得通，但没排除中途的校验。
- **confirmed：** 最小输入或测试在授权构建上重复触发缺陷，或两个身份的差异违反已写明的访问规则。

不可达、仅调试构建、或设计上允许的管理员操作，写成 rejected，并留下原因。

## 变体和「哪一版引入的」

变体分析找的是同一缺陷逻辑，不是同一字符串。用补丁改过的源和 sink 写查询，在本仓库和其他版本上跑。文本搜索只能当起点。

定位引入提交时，不要只在旧版本上重放同一个崩溃输入：接口和触发条件会变，环境也会坏。更稳的是看缺陷逻辑还在不在（SymBisect 用受约束的符号执行找这个逻辑，而不是盲重放 PoC）。没有补丁时，用缺陷模式而不是用「已经武器化的输入」去二分。
