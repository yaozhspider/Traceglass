# 按表面查（本地摘录）

先选表面，再回到缺陷类。不要把清单当成每一项都要做的渗透步骤。

## Web 与 API

OWASP WSTG 是技术地图，不是清单。自动化 DAST/SAST/SCA 负责广度，业务规则靠人。WSTG 自己写明：最严重的问题经常缠在业务逻辑里，通用扫描器缺少应用上下文。

优先看：

- 身份：未登录、普通用户、另一个普通用户、管理员。每个写操作都做交叉。
- 对象 id 由客户端提供的接口（对应 CWE-639）。
- 把输入拼进查询、命令、HTML、URL 的地方。
- 文件路径和上传后的处理者。
- 服务端去请求用户指定 URL 的功能。只对测试桩发请求。
- 错误处理是否把内部路径、堆栈和令牌返回给客户端。
- 状态机：支付、重置密码、邀请、审批能否跳步或重放。

配置项（安全头、HTTP 方法、备份文件、云存储权限）放在侦察里记录。缺一个安全头通常是加固建议，除非它直接让已确认的注入或会话问题成立。

## 原生用户态

入口通常是文件、套接字、IPC、动态库回调。危险点是解析循环、长度字段、整数到 `size_t` 的转换、以及把外部长度传给拷贝。

有源码：对解析函数写 harness，ASan 构建。  
无源码：先找到读入函数和后面的拷贝，再决定是否值得做二进制 fuzz。脱壳或加固过的二进制先用 unpacking skill 恢复可分析映像，再开始本流程。

## 内核与驱动

入口是系统调用、设备节点、ioctl、文件系统和网络栈。用户指针在内核里使用前必须有明确的拷贝长度和生命周期。并发的打开、关闭、ioctl 是竞争的常见位置。

确认依赖 KASAN、KMSAN、锁依赖检测器或能稳定复现的 Oops，并且符号能对上源码行。没有授权的内核调试环境就不做动态测试。

## 移动与托管

Android：除了 Java/Kotlin 的 WebView、路径和 Intent 跨组件调用，还要看 JNI 里把 Java 数组长度用错的拷贝。加固包先按脱壳 skill 得到真实 DEX，再审计。  
.NET 与 Java：反序列化、XXE 类的解析器配置、以及把用户字符串拼进查询。IL 或字节码看不清时先恢复，再做数据流。  
JavaScript/Electron：把不可信页面内容送进有节点权限的 API，以及把用户路径传给 shell。

## 协议与固件

按状态机读规范：谁可以在这个状态发这种帧，长度字段是否覆盖到下一层。符号执行和 fuzz 只挂在解码函数上。固件先确定架构和可加载的解析代码，不要对整包镜像做无入口的扫描。

## 供应链

锁定文件、构建脚本、安装钩子和下载 URL 都是入口。可疑点是：安装时执行远程脚本、构建从可变标签拉依赖、密钥进仓库。已知 CVE 按 static-and-variants 里的「是否调用到」处理。

## 证据不够时怎么写

缺构建、缺第二个测试身份、或 fuzz 还没稳定复现时，报告保持 hypothesis，并写上下一步需要的最小条件（ASan 构建、一个低权限账号、一份合法种子）。不要用影响更大的猜测填空。
